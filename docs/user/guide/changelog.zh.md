# 每个版本改了什么

[English](changelog.md) | 中文

每个已发布版本一节，最新在前。每节按「用这个产品的人得到了什么、失去了什么、需要做什么」这个顺序写；逐项的迁移步骤在[升级指南](../../upgrade-guide)里，本页只链接而不重述。

一个版本有了标签才会出现在这里。条目在改动落地时就写，而不是等版本发布，所以未发布那一节会一直累积到打标签为止。

## 未发布

### 新增

- **设置里的个人平面。** 一个人读取和更改属于自己的东西——自己的指令、自己的记忆、自己可以用什么、自己的会话数据——与管理员维护的东西分开。导航现在把分区分成个人平面与管理平面两组，管理平面只提供给确实在管理某样东西的身份：没有账号体系的部署，或高于 `member` 的角色。这个切分是导航而非授权——每个管理类调用都保留自己的检查。
- **日语、西班牙语、法语、德语、俄语、葡萄牙语**在浏览器端与桌面端上线，与英语、中文并列。每个随产品交付的插件现在都带这八种语言的名称与说明。
- **从本机页面设定品牌。** `lyn --profile brand-setup` 打印一个一次性令牌，并提供一个页面，把这个部署自己的品牌——名称、图标、主题色——写进某个 profile 的补丁层。它只绑定 `127.0.0.1`，并随进程结束。

### 变更

- **终端、`ralph` 工具、会话检索、徽章 skill 与 webhook 入站留在默认产品里。** 上游把这些移进了它的实验组；本安装把它们留在企业部署一打开就能找到的位置。
- **遥测仍然关闭，而且现在能被证明。** 会话上传出厂即 `DISABLED` 且无端点，并有一条行为测试断言：在默认环境下给出反馈不会产生任何外发请求。桌面产品分析只到运维通过 `LYNESS_PRODUCT_ANALYTICS_OTLP_URL` 指定的 collector；没有厂商默认值。
- **每个 Remote 命名空间都声明它所需的身份。** 不具备该身份的调用在「每个线上调用都要经过」的那一处被拒绝，而不是在每个方法里各判一次。

### 修复

- **`lyn --profile brand-setup --help` 现在打印帮助并退出。** 它此前会启动服务、绑定端口并永不返回。
- **hosted 与 enterprise profile 现在带账户与积分。** 两者都选了这两个模块，但安装并不依赖它们，于是启动器只警告跳过，部署实际两样都没有。
- **会话归属重新被记录。** 挂载会话归属曾导致会话创建直接失败；归属与租户记录现在写在「新会话最早能接受事件」的那一刻。

## 怎么读一条条目

**新增**是原本没有的能力。**变更**是行为变了的能力，包含某个部署可能依赖过的默认值。**修复**是使用者本来可能撞上的缺陷。需要在升级时动手的改动会带一个指南链接；不需要的，就以「没有链接」表示。

条目写的是一个人或运维看得见的东西。谁都观察不到的重构不出现在这里——那段历史在 [Agent Notes](../../../.agents/notes/README.zh.md) 里。
