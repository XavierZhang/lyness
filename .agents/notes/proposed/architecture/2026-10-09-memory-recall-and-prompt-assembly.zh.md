# Agent Note: agent 记住什么、能查什么，以及它的提示词如何组装

Status: proposed

[English](2026-10-09-memory-recall-and-prompt-assembly.md) | 中文

## Problem

三件相关的事都不对，而且以三种不同的方式不对：一项能力完全缺席，一项建好了却够不到，一项在位却未经检视。

**没有任何东西跨会话记住任何事。** 树里没有 memory 包。[`goal`](../../../../packages/goal/goal/README.zh.md)、`todo` 与 `plan` 持有的状态都在一个会话之内，随它一起结束。每次对话都让 agent 从零开始：这个组织怎么称呼事物、哪个仓库要紧、上周定了什么，全部重讲一遍。对一个卖给组织的产品而言，这就是"工具"与"同事"之间的差别。

**检索建好了、测过了，一个地方都没挂。** [`lyn-tool-session-query`](../../../../packages/session-query/tool-session-query/README.zh.md) 给模型五个只读工具，用来搜索早先的会话、查看命中、追踪关系、读取精确事件，而跨会话访问只在目标会话的 `cwd` 与调用方完全一致时才被授权。[`session-query-sqlite`](../../../../packages/session-query/session-query-sqlite/README.zh.md) 是它的后端。没有任何出厂 profile 挂载这个工具，而 Web 补丁把索引钉在 `openAt: never`。能力存在而没有客户够得到——正是[默认模块笔记](2026-10-08-default-modules-and-views.zh.md)要修的那种失败。

**提示词是组合出来的，但没有分层。** [`lyn-system-prompt`](../../../../packages/core/system-prompt/README.zh.md) 把段落、运行时事实与变量组装成一份有序的提示词，并在组合不合法时让组装失败，而不是发出一份畸形的提示词。它没有承载的是：哪些部分跨请求稳定、哪些每轮都变。于是缓存行为是附带产生的：一个易变事实和一个固定身份处在同一个有序列表里，所以任何会动的东西都可能让它之前的一切失效。

**而工作区的指令文件是未经检视就被读进来的。** [`lyn-agent-instructions`](../../../../packages/context/agent-instructions/README.zh.md) 在一个字节预算之下把适用的 `AGENTS.md` 链加载进提示词，先丢掉更宽泛的文件，再去截断最具体的那个。它检视这些字节只看大小，别的一概不看。在开发者自己的机器上这正是它的用意——那个文件就是他给自己 agent 的指令。在托管基础设施上，仓库可能来自任何地方，它就是一条通往模型的指令通道，而客户从未授权它、也看不见它。

## Proposal

声明提示词层级，给 agent 一份组织可审计的记忆，让检索默认开启，并把指令文件当作不可信输入。

### 每个提示词段落声明自己的层级

三层，靠声明而不是靠推断：

- **稳定层**——harness 身份、部署人格、工具指引、技能目录。随组合变化而变。
- **上下文层**——工作区指令链与项目文件。随工作区变化而变。
- **易变层**——记忆快照、行事的成员身份、时间。

组装器先按层级排，再按既有的段落顺序排，于是请求层知道是哪一层动了。只有易变层变化时，只重建易变的尾部，稳定前缀保持**逐字节相同**——而这正是让供应方的前缀缓存根本可用的前提。今天这个性质是偶然得来的；声明层级让它变成组装器能够守住的性质。

### 记忆属于某个成员身份，而组织看得见它

记忆以写下它的那个成员身份为范围，另有一个组织级层级，承载管理员向全体发布的事实。它只由显式操作写入——人或 agent 说"记住这个"——绝不在后台从会话记录里采集。

组织可以列出并删除为其成员持有的一切。这不是一条功能请求；这是能够持有这些数据的前提条件。

记忆会进入模型请求，所以仓库的那条规则毫无例外地适用：**模型可见即被记录**。进入请求的记忆可以从会话日志重建，这意味着一个记忆块是一个会话事件，不是一份看不见的旁路输入。

### 检索转为默认开启，而授权规则一字不改

`tool-session-query` 挂载到每个服务于人的 profile 上。它那条 `cwd` 完全一致的跨会话规则原样保留——它是一个会话读到另一个会话之间唯一的屏障，而放宽它不属于本次改动。

内容索引不再被钉死。Web 补丁里的 `openAt: never` 变成一项部署与计划的决定，于是托管组织可以拥有全文检索，而不想要这个索引的部署仍然可以拒绝它。

### 工作区指令文件是不可信输入

指令链在并入上下文层之前先被检视，而被丢掉的内容记录在人看得见的地方。同时要带上那条诚实的限制：检视不是保证，本笔记也不声称它是。

真正的边界是结构性的，不是文本性的：**指令文件可以措辞指引，不能授予能力。** 它不能启用一个工具、提升沙箱模式、改变审批策略，或变更额度。这些是由各自拥有它们的那些操作做出的决定，正如[插件信任](2026-10-08-plugin-compatibility-and-trust.zh.md)与权限预设已经要求的那样。检视减少的是一个恶意文件浪费一轮的频率；让它造不成损害的，是那条能力规则。

### 记忆与知识库是两回事

[默认模块笔记](2026-10-08-default-modules-and-views.zh.md)给产品定了一个知识模块：客户的文档，建好索引，作为工具可达。记忆不是那个。文档在别处写成、经过审核、有版本、体量大；记忆体量小、可变、在工作中写下、讲的是这个组织怎么运转。它们的写入路径不同、生命周期不同、审核不同。不存在任何路径经由其中一个写入另一个。

## Alternatives considered

**从会话记录自动采集记忆。** agent 不需要任何人额外做事就能学会，而"自我改进"通常指的就是这个。否决：它写下的是客户从未批准、也无法审计的事实，并且把每一次对话都变成后续对话的一份静默输入。一个组织无法就自己员工的对话接受这件事。

**一个组织一份记忆。** 存起来和展示都更简单。否决：一位成员半成形的草稿会变成每位同事的上下文，而第一条错误的记忆会误导整个组织，而不只是一个人。

**把记忆放进知识库。** 一个检索界面、一个索引。否决：文档有审核有版本，记忆两者都没有，并出来的界面得同时承载两套策略，而它会默认落到更弱的那一套。

**检索继续保持可选。** 它确实有成本——按该包自己的概要所述，每次请求多五个工具 schema 加固定指引。否决：它已经建好、测过、却够不到，而没人够得到的能力，其价值低于它那份提示词成本的昂贵程度。

**放宽 `cwd` 规则，让检索覆盖一个组织的会话。** 检索会更有用。在此处否决：那是一项有自己影响范围的独立决定，把它塞进"挂载一个既有工具"里，等于用一次组合变更夹带了一次权限变更。

**不做检视，依靠沙箱。** 沙箱本来就约束命令能碰什么。否决：沙箱约束的是作用，不是指令。一个说服 agent 在其权限之内做有害之事的文件，永远不会触发它。

**把指令文件当作受信任的一层。** 在开发者的机器上它确实是。在托管上否决：仓库的作者与客户不一定是同一个人，而产品单凭文件本身分辨不出自己处在哪种情形。

## Acceptance criteria

- 每个提示词段落声明层级，且只有易变层变化时稳定前缀逐字节相同。
- 记忆只由显式操作写入，以写下它的成员身份为范围（除非管理员已将其发布到组织），且组织可以列出并删除其全部。
- 进入模型请求的记忆可以从会话日志重建。
- `tool-session-query` 挂载在每个服务于人的 profile 上，且其 `cwd` 完全一致的跨会话授权不因本次工作而改变。
- 内容索引是一项部署与计划的决定，而不是一个钉死的值。
- 工作区指令链在并入提示词之前被检视，且被丢掉的内容对人可见。
- 指令文件不能启用工具、提升沙箱模式、改变审批策略或变更额度，且每一条拒绝都在做出该决定的那个操作处得到验证。
- 不存在任何路径经由知识库写入记忆，或经由记忆写入知识。

## Risks

**分层是一个关于别人缓存的论断。** 声明一个稳定前缀并不能让供应方尊重它，而一个把整份提示词重读一遍的供应方会让分层成为看不见的功夫。组装器一侧的那个性质仍然值得拥有，但好处不由我们保证。

**记忆会是平台持有的最敏感的东西。** 它体量小、可被引用、关于具名的人和他们的工作，而且会进入模型请求。这里泄漏一次，比泄漏一批客户在别处本来也有副本的文档更糟。

**检视会产生误判。** 一份措辞强硬的正当指令文件看起来像一次攻击。静默丢掉它会削弱客户本意的指引，这正是"被丢掉的内容必须可见、而不只是记进日志"的原因。

**默认开启的检索扩大了一个会话能读到的范围。** 每次请求多五个 schema 是明面上的成本；没说出来的那个是，`cwd` 那条规则从此承载真实流量。它当初是作为一个可选工具的护栏写的，现在成了一个出厂默认的护栏。

**记忆与知识在界面上会被混淆。** 客户会问为什么"要让 agent 知道的东西"有两个地方放。在包层面把它们分开，并不能在客户头脑里把它们分开，这两个界面将需要互相解释。
