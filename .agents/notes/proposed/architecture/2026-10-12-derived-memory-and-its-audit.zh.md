# Agent Note: agent 自己推导出的记忆，以及让它可被撤销的那份依据

Status: proposed

[English](2026-10-12-derived-memory-and-its-audit.md) | 中文

## Problem

[记忆那份决定](2026-10-09-memory-recall-and-prompt-assembly.zh.md)否决了从会话记录推导记忆，理由是它"写下客户从未批准、也无法审计的事实"。前半句是客户可能愿意做的一笔交易；后半句才是真正的反对意见，而它是实现的性质，不是这个想法的性质。

拒绝的代价是真实的。只靠显式写入意味着：只有当有人想起来要求时，一条事实才会被保留——于是一个组织实际赖以运转的那些约定，恰恰是因为"人人都知道所以没人说出口"而永远写不下来的那些。Mem0 的抽取-更新循环存在，就是因为这个缺口是常态而不是边缘情形。

而按被否决的那种方式允许它，代价同样真实。会自己写入的存储会持有一些没人能重建其来源的事实：错的那条无法追溯到产生它的东西，客户分不清哪些记忆是自己授权的，而移除一条坏的会销毁"它曾被使用过"的唯一证据。

所以问题不是要不要推导，而是：一条推导出的记忆，能不能带上足够多的自身历史，使它可被审阅、可被撤销。

## Proposal

允许推导，而每一条推导出的记忆都带上它的来源、被记录在它来自的地方，并且可以在不擦除记录的前提下被失效。

### 来源是一个字段，不是一条惯例

每一条记录它是如何存在的：是人要求的，还是 agent 推导的。推导出的条目额外记录它来自哪个会话的哪一轮。

没有这个字段就没有审计，只有一份清单。有了它，"这条是从哪来的"就有了一个不依赖记性的答案，而本笔记其余各处也才能把两类区别对待。

### 一次推导被记录在产生它的那个会话里

这次写入作为事件追加到**来源会话**的日志里，而不只是写进记忆存储。审阅者正是去那里看：那一轮就在眼前，而由它推导出的断言紧挨着它。

这让审计有了能对上的两头。从一条记忆出发，它的来源点明一个会话和一轮；从一个会话出发，它的日志点明那一轮产生了哪些记忆。任一方向都能回答这个问题——这正是让一次错误推导"可被找到"而不只是"被记下来"的东西。

### 失效不是删除

被证明是错的推导记忆会被**失效**：它不再进入任何请求，而记录连同理由与时刻留下来。删除它会销毁"它整整一周出现在每个请求里"的证据，而那恰恰是一个正在复查某个糟糕答复的客户最需要的东西。

显式删除仍然为另一种情形保留：那种本就不该被存下来的记忆，而不是存下来之后被证明是错的那种。

### 推导那一类永不压过显式那一类

提示词承载的是最新条目的一个有界集合。推导条目远比显式条目多，所以单凭时间新旧，就会让一个人亲口说过的约定被关于他的推断挤出那个块。

因此显式条目先占预算，推导条目填补剩下的。只想要自己说过的内容的组织，可以把推导的份额设为零而不必关掉推导——审计轨迹继续累积，同时没有任何推导内容到达模型。

### Mem0 的四种操作落在已有的东西上

抽取提出操作，其中三种已经有自己的家。`ADD` 是一条新的推导条目。`UPDATE` 是 `supersedes` 那次写入，它在一次持久操作里替换，而不是留下一个变更过约定的两半。`DELETE` 是失效。`NOOP` 什么都不写，而且是常见结果。

这个循环不增加第五个动词——这正是关键：推导改变的是谁来写，不是一次写入意味着什么。

### 推导的代价要说出来，不要藏起来

抽取是它所检视的每一轮上的一次模型请求，所以它是配置——检视哪些轮、以及是否运行——而不是一项永远开着的后台行为。什么都不为它付费的部署应当也能用这个产品，而为它付费的部署应当能在"失效"所用的同一份审计里看到自己买到了什么。

## Alternatives considered

**继续拒绝推导。** 这是当前的决定，也是最简单的说法：每一条记忆都是有人要求的。否决：它保留了那个让推导显得有吸引力的缺口——人人都知道而没人说出口的那些约定——而当初写明的反对意见是可审计性，来源字段回答了它。

**推导进一个由人批准后才入库的队列。** 任何未批准的内容都不会到达模型，这是对原始反对意见最严格的读法。作为默认否决：没人去清的队列是一个什么都不做的功能，而批准的工作量随对话量而不是随价值增长。对想要它的组织，这仍是对的形态——作为同一个来源字段之上的一条策略，而不是第二套机制。

**把推导记忆与显式记忆分开存。** 两个存储让两类不可能被混淆。否决：一个存储加一个来源字段回答同样的问题，而两个存储会需要两套保留、两份提示词、以及两份必须彼此一致的审计。

**错的推导记忆直接删除，而不是失效。** 状态更简单，而且要求移除的客户通常就是指移除。否决：那条记录正是"这条记忆在被抓到之前一直出现在每个请求里"的证据，而这恰恰是一个正在复查糟糕答复的客户在找的东西。

**让提示词预算只按时间新旧决定。** 这就是有界块现在的做法，不需要新规则。否决：推导条目数量压过显式条目，于是那个块会被推断填满，而把一个人真正说过的约定挤掉。

## Acceptance criteria

- 每一条记录它是人要求的还是 agent 推导的，且推导条目记录它来自哪个会话的哪一轮。
- 一次推导向来源会话的日志追加一个事件，使那一轮与由它推导出的断言可以一起读。
- 被失效的条目不进入任何模型请求，且仍然可读，连同它的理由与被失效的时刻。
- 显式条目先于推导条目占用提示词预算，且部署可以把推导份额设为零而推导继续运行。
- 抽取只在配置说它运行的地方运行，而它花了多少可以在"它写了什么"的同一处读到。
- 一条取代另一条的推导条目在一次持久写入里完成替换，且失效与删除保持为不同的操作。

## Risks

**来源可以是错的，而且错得不可检测。** 一次推导点名的会话与轮次，是抽取器**以为**自己读到的东西。如果抽取跨多轮做了概括，被记录的来源是"可得的最好答案"而不是一个证明；把它当成证明的审计会误导人。

**审计轨迹本身也是敏感数据。** 来源把一个关于某个人的断言，系到产生它的那次具体对话上。被失效的记录在该断言停止使用之后仍保留这条系带，所以持有大量失效推导的存储，就持有一部关于具名的人的长长的推断史。

**推导是一项随对话量而非随价值反复产生的模型成本。** 它随人们说多少话而增长，而大多数轮次产出 `NOOP`。部署可以调节检视哪些轮，但形态就是：最忙的客户为最少的新信息付最多的钱。

**失效需要有人察觉。** 这里没有任何东西能检测出一条错误的推导记忆；它做到的是"一旦被发现就可被撤销"。失败形态是一条听起来合理、没人质疑的错误事实——它持续进入每个请求，恰恰因为它读起来很合理。
