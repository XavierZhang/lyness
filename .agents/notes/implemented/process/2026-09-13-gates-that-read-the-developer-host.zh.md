# Agent Note：读取开发机状态的门禁

Status: implemented

[English](2026-09-13-gates-that-read-the-developer-host.md) | 中文

## Problem

四项检查在开发机上失败、在 CI 上通过。没有一项是产品缺陷，也没有一项来自本 fork 的改动：它们各自读取了一个自己从未声明的宿主事实。

其中两项读取进程环境。Windows 可执行文件解析器的测试，为它断言的搜索语义继承了 `process.env`，于是一台导出了 `NoDefaultCurrentDirectoryInExePath` 的宿主会丢掉期望列表里的目标 cwd 探测——实现是对的，测试量的是开发者的 shell。Python 运行时的环境隔离测试断言子进程看不到 `PATH`，这对解释器二进制成立，对版本管理器的 shim 不成立：pyenv 的 `python3` 是一个 shell 脚本，它先导出自己的 `PATH` 再 exec 真解释器，于是断言量的是包装脚本，而不是运行时构造的环境。

一项读取文件系统。一份 vite 夹具用绝对路径指定构建 input，而 vite 会对自己的 root 做 realpath；macOS 的平台临时目录是符号链接，两者因此不一致，产出的资产名变成一条逃出 root 的路径，rolldown 拒绝它。

一项读取构建产物。语料库导入门禁只在失败信息指向 dockkit **自己的**样式表时豁免它。构建产物把 primitives 依赖外部化并先 import 它，而那个包因同样的原因也在豁免名单里，于是 loader 报的是**那个包**的样式表——该条件永远不可能成立。它一直没暴露，是因为在没有构建产物的树上该套件会 skip，而默认的测试运行不会先构建 host 库。

## Decision

每项检查都声明自己需要什么，而不是继承。两项读环境的显式传入环境：解析器测试为每个裸命令固定一个空环境，Python 测试固定 `sys.executable` 报告的解释器。夹具规范化自己的根目录。语料库门禁接受来自 dockkit 自身**或**来自另一个其产物同样因样式表被豁免的包的样式表拒绝，而这个集合是从豁免表推导出来的，不是再钉一条路径。

没有改动任何实现。四项中有三项本来就是对的，第四项是门禁本身。

## Alternatives considered

**把语料库豁免放宽到任意被拒绝的样式表。** 一行改动，真实语料库就能通过。但它同时删掉了那道防护：该套件有一个负例，断言 dockkit 自己引入的、除已命名之外的样式表仍要被报告，而这个负例会失败。这种收紧是有意的，值得保留。

**把依赖的样式表钉成第二条期望路径。** 符合该文件「宁用钉住的清单而非计数」的主张。但它钉的是依赖恰好最先 import 的那个样式表，既不属于 dockkit 的关切，也不稳定；而且会因启动方式而不同——支持 paths 的 loader 把依赖解析到源码，裸 loader 解析到构建产物。

**改造宿主而非仓库：取消那个环境变量、让 `python3` 指向二进制、换掉临时目录。** 完全不动仓库。但这会让「跑绿」成为某台机器配置的属性，而这正是被修的那个毛病；此后每位贡献者都会重新发现同样的四个问题。

**放着不修，登记为已知的宿主噪音。** 最省事，也是它们到来时的状态。但一个长期有红项的套件会没人再看；而且这四项里有两项是可移植性缺陷，Windows 或 macOS 的贡献者会把它们当作产品行为而非测试噪音撞上。

## Consequences

这四处改动位于上游文件中，因此登记在 fork 台账里；若上游自己的修复落地，合并时会以冲突形式相遇。它们并非 fork 专有，是可以反馈给上游的候选：其中没有任何一点依赖改名或本 fork 的配置。

语料库门禁现在从 `BASELINE_EXEMPT` 推导它的「继承样式表」允许范围，因此从该表移除一个包，dockkit 的允许范围会随之收窄，豁免仍然只有一处定义。
