# Agent Note：真实 API e2e 调用哪个平台由配置决定，而不是写死

状态：已实现

[English](2026-09-22-configurable-e2e-platform.md) | 中文

## 问题

真实 API 的 e2e 测试可以通过 `DEEPSEEK_BASE_URL` 指向其他兼容 DeepSeek 的平台，但目标的其他方面都不可配置。大约二十个测试把官方模型名 `deepseek-v4-flash` 写成字面量，而产品内置目录里只有官方名字，因此每个取应用默认模型的 web 与 profile 测试，都会向另一个平台请求一个它并不提供的模型。对官方以外的任何平台运行都会失败，而失败原因反映的是平台，不是代码。

最直接的修法——每个测试各加一个替换目录的 overlay——意味着要改大约四五十个上游测试文件，每一个都是下次上游改动该测试时等着发生的合并冲突。

## 决策

平台由产品本来就在读取的变量决定。`@lyness/lyn-llm-deepseek` 新增 `DEEPSEEK_MODELS`：逗号分隔的模型目录，与 `DEEPSEEK_BASE_URL` 从同一组受信任的环境层读取；新增的测试支撑包 `@lyness/lyn-e2e-target` 则从同一个变量解析测试要发送的模型。环境变量会传到测试启动的每一个进程，因此 web 与 profile 测试完全不需要改。

四条裁定决定了它的形状。

**该变量替换组合配置的目录，已保存的目录仍然优先。** 为一个端点写的目录对另一个端点是错的，合并会提供所选端点并不提供的模型。替换后的目录成为设置的基础层，用户自己保存的目录仍在其上——这正是模型设置页原有的优先级。

**保留 schema 默认值。** 若要区分「已配置」与「取默认」，就得去掉 `models` 的 schema 默认值，而模型设置页正是把该默认值渲染成提供方的目录。在上一层替换组合配置的值，页面与未配置时的运行时行为都保持原样。

**官方独有功能跳过而不是失败。** 提示词缓存计量，以及 Claude Code 子进程使用的 Anthropic 兼容端点，只存在于官方 API。在其他目标上这些测试会跳过，原因写在测试标题里，因为那里的红灯反映的是平台。Claude Code 测试原先在非官方端点上直接抛错，现在改为跳过。

**未设置即官方。** 两个变量都未设置时，每个测试调用的对象与之前完全相同；fork 的 CI 与上游一样显式设置端点，因此误留的 `.env` 无法改变一次运行的去向。

## 考虑过的替代方案

**每个测试各加一个替换目录的 overlay。** 不改产品。但要动四五十个上游测试文件，而且以后每个新测试都得记得这么做。

**加一个只给测试用的变量，比如 `LYNESS_E2E_MODEL`。** 加起来简单。但它允许测试与产品不一致——测试要一个模型、应用提供另一个——而这正是本次要消除的失败。

**在提供方里做「逻辑模型名到线上模型名」的映射。** 测试可以继续写 `deepseek-v4-flash`，由提供方发送平台自己的名字。这会引入提供方原本没有的别名概念，而唯一的使用者是测试。

**像上游一样把 e2e 钉死在官方 API。** 什么都不用改。但本 fork 服务的租户会通过自己的网关访问 DeepSeek，测试应当也能证明产品在那里可用。

## 影响

私有化部署同样可以把提供方指向使用自有模型名的第三方 DeepSeek 端点，而无需修改组合配置。每个 id 都成为仅文本、使用默认上下文窗口的条目；需要图片输入的模型仍要在设置里单独配置。

测试每次运行只用一个模型：变量列出的第一个 id。

本次改动涉及一个上游产品文件、约二十处把字面量换成 `E2E_TARGET.model` 的上游测试、两个改为经 `!!js` 读取该变量的 YAML fixture，以及官方独有功能的门槛；均已记入 `CUSTOM.md`。

以上都还没在真实端点上跑过：本工作区没有密钥，fork 的 Actions 也因账单被锁。测试在无密钥时能正常加载并自行跳过，提供方的改动由单元测试与设置层测试覆盖。
