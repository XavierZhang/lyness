# Agent Note：品牌图标由 PNG 描边生成

Status: implemented

[English](2026-09-15-brand-icon-from-png.md) | 中文

## Problem

私有化部署提供三个品牌 SVG——图标、favicon 与字标——每一个都会到达每位访问者的浏览器。SVG 是浏览器解释执行的文档，不只是一张图：它可以携带脚本、事件处理器，以及从别处加载内容的引用。图标来自运营方上传或生图模型。两者都不能被信任会产出安全的文档，也都不能稳定地产出干净的文档：模型的输出是位图，运营方的文件可能带着编辑器元数据、嵌入的位图，或无视页面主题的固定颜色。

## Decision

图标一律以 PNG 输入，每一个 SVG 都由本工具链自己的写出器产出。`@lyness/lyn-host-brand-icon` 在解码前先读取 PNG 文件头，把图片铺到白底上，把比中灰更暗的像素当作图形，拒绝无法做成图标的输入，裁到图形范围，再用 `@neplex/vectorizer` 的黑白预设描边。它把每个被描出形状的位移折算进坐标，因此图标是填充为 `currentColor` 的普通路径，坐标框恰好等于图形大小；同样的路径被居中放进一个正方形 favicon，在暗色配色方案下变白。

`isBrandSvg` 只接受图标包与字标包写出的文档：尺寸与 `viewBox` 一致的根元素、一条可选的固定暗色规则，以及路径数据只含移动、直线、曲线与闭合命令的路径。它是输出的语法，而不是作用于任意 SVG 的过滤器，因此任何不是这两个包写出的输入形态都无法通过。

## Alternatives considered

**接受 SVG 上传，再做净化。** 已有矢量原稿的运营方可以保留全部精度。但净化 SVG 意味着要让允许名单持续跟上浏览器会执行的每一种元素、属性与 URL 形式，而且它仍会放过不跟随页面主题的结构与颜色。从 PNG 描边会损失矢量原稿的精度，但彻底消除了「上传的 SVG」这一类输入。

**potrace。** 黑白图描边的参考实现，曲线最干净。但它的 JavaScript 移植版是 GPL-2.0 许可，随私有化部署包分发会带上公开源码的义务。

**imagetracerjs。** 公有领域许可，纯 JavaScript。但它自 2023 年以来没有发布新版本，出了缺陷上游不会修复。

**在描边器前面另加一个 PNG 解码器，比如 pngjs。** 一个常见的纯 JavaScript 依赖。但 `@neplex/vectorizer` 本身就能解码图片并对原始 RGBA 像素描边，再加一个解码器只会多一个依赖，删不掉任何代码。

**用通用的 SVG 优化器清理描边器输出的 SVG。** 描边器会写出 XML 声明、注释，以及每条路径上的 transform，优化器能把它们整理掉。但这样文档的格式就由两个库的行为决定，而不是由本包决定；而且要验证它，仍然需要本包直接写出的那套语法。

## Consequences

描边在原生插件里运行。`@neplex/vectorizer` 为 14 个目标平台发布了预编译二进制，包括 macOS、Linux 与 Windows；它被精确锁定在 0.1.0，因为 1.0 之前的描边器任何一次发布都可能改变输出。没有预编译二进制的平台无法加载它。

亮度阈值会丢弃颜色。多色 logo 会变成单色，白底上的浅色图形会因为没有图形而被拒绝。四个角都是深色的图片会被当作深色背景拒绝，这也会拒绝恰好占满四个角的图形。

每一条边界都来自 Web 壳或描边本身：每边至少 1024 像素，曲线才能拟合干净；至多 4096 像素，一次解码占用的内存才有上限；宽高比 1:1 到 1.4:1，图标才放得进侧边栏 24px 高、旁边还有产品名的那一行；至多 64 个形状，照片才会被拒绝，而不是被描成几百条路径。favicon 里图形占正方形的 96%，与 Web 壳自己的 favicon（96.6%）一致。
