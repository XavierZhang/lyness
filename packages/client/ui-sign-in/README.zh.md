# @lyness/lyn-client-ui-sign-in

[English](README.md) | 中文

## 概述

`lyn-client-ui-sign-in` 是一个人进入「服务有名有姓的人」的部署的方式：在没人登录时盖住产品的一块屏，按部署挂载的渠道各给一个按钮；以及通用设置里说出这是谁的会话、并提供出口的一行。两者读同一个来自 `remote.identity` 的答案，于是打开设置与加载框架不会问部署两次。在没有账户的部署上两者都不渲染，单操作者形态毫无变化。

<a id="use-this-package"></a>
## 使用本包

Web bundle 把两侧与它们读的那个命名空间并列挂上：

```yaml
- id: identity-controller
  name: '@lyness/lyn-api-identity-controller'
- id: ui-sign-in
  name: '@lyness/lyn-client-ui-sign-in'
```

别的都不用配。出现什么由答案决定：没有账户就什么都不渲染，有账户而没人登录就盖住产品，已登录的访客只看到设置里那一行。

<a id="understand-the-implementation"></a>
## 理解实现

**这块屏盖住产品，而不是摆在它旁边。** 页面上其余每个界面都即将被拒绝——Remote 授权规则会挡回未出示身份的调用——而在那之下渲染出来的产品，是一整页错误状态。

**框架一起来它就问。** 其余每个界面的调用都依赖这个答案，所以等一次交互再问，等于让人先经历一整页拒绝。

**答案到达之前什么都不显示。** 每次加载前先闪一下的屏，比晚一瞬出现的屏更糟，所以还没答复的读取渲染空白，而不是渲染一个猜测。

**渠道是链接，不是调用。** 登录要离开去目录自己的页面，登出要清一个 cookie；两者都不可能发生在一次 RPC 里，所以都是跳转到部署汇报出的那些路径。

**一次读取，两个界面。** 屏与行回答同一个问题，绑定把一个结果发布给框架已经烘出的每一个 store。一个人登录之后，屏消失与行填上，来自同一个答案。

**刷新失败时保留已经读到的。** 因为网络抖一下就把访客清空，会用一块登录屏盖住一个已登录者的产品。

<a id="model-experience"></a>
## 模型体验

没有，因为本包不注册任何工具或提示词：它是一个人在会话存在之前看到的东西，它渲染的一切都到不了模型请求。

#### KV 缓存影响

请求前缀不变，因为这里没有任何东西进入被组装的请求。

## 已知限制与未竟事项

<a id="known-limitations-and-deferred-work"></a>

- **这层遮盖是一种提供方式，不是执行** —— 服务器无论如何都会拒绝未出示身份的调用；从控制台把这块屏关掉的人，看到的是一整页拒绝，而不是任何人的数据。
- **不支持自驱渠道** —— 只提供浏览器能被送过去的渠道；在「拥有浏览器的那个进程」里完成的渠道被略过，因为服务器没地方送这个人。
- **没有身份可选** —— 在两个组织都有身份的人，以其会话携带的那一个行事；这一行说出那一个，不提供其余的。
- **没有东西说明登录为何失败** —— 回调路由自己汇报拒绝，而人回到的这块屏只是再次展示渠道。
- **它不会自己刷新** —— 答案在界面挂载时读一次，所以在另一个标签页里失效的会话，在有人再问之前仍显示为已登录。

**运行时不变量：** 不发布伴生检查。两个界面渲染同一次读取的结果，而绑定是它唯一的发布者。
