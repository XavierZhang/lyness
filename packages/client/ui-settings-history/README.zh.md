# @deepseek-ai/dsh-client-ui-settings-history

[English](README.md) | 中文

## 概述

`dsh-client-ui-settings-history` 是管理员读那份记录的设置区块。一次读答出他的身份可以看到的那些已记录的更改，最新的在前，每个条目显示哪条记录变了、它发生了什么、是谁做的，以及每个有差异字段的两边。它在构造上就是只读的：那份记录在服务端只会被追加，所以这里没有东西可编辑或删除。

<a id="use-this-package"></a>
## 使用本包

Web 应用把它挂在它所展示其更改的那些区块旁边：

```yaml
- id: ui-settings-history
  name: '@deepseek-ai/dsh-client-ui-settings-history'
```

没有要配置的。这个区块以 order 50 注册进 `settings.section`，排在机器人之后，并在被打开时读 `remote.audit`。一次导出以下载的形式交给读者，浏览器和桌面外壳各自把它存到那个平台存下载的地方。

<a id="understand-the-implementation"></a>
## 理解实现

**在构造上就是只读的。**那份记录在服务端只会被追加，所以一个提供编辑或删除条目的界面，提供的是部署会拒绝的东西。这个区块展示并刷新，别无其他。

**三个答案，其中只有一个值得一个重试按钮。**一个不保留记录的部署不会在读者等待时长出一份来，一个没有相应身份的调用方也不会因为再问一次而获得它。只有读坏了的那一种才给按钮。

**这次读不点名组织。**命名空间会解析出调用方身份所管理的那一个，于是这个界面没有一个会填错的组织字段——而一个管得到所有组织的平台身份，读的就是所有组织。

**这个构建不认识的那一类，按服务端给的名字显示。**可管理记录的集合是开放的，所以后来的拥有者在这里读起来是它自己，而不是一片空白。

**空值会被点出来，而不是不显示。**一个被改成空字符串的字段是一次值得读的更改，所以那一行会说出来，而不是在该有值的地方留一个空缺。

**导出就是同一套翻页，写出来而已。**它用这个界面本来就在用的那一次读从最新往回翻，所以不需要第二个服务端界面去和第一个保持一致。每行一个 JSON 对象，就是命名空间答出来的那个样子：CSV 必须把那些变更字段摊平或者字符串化，而那恰恰是审计者来看的东西。一页被拒绝就停下来、什么也不写，因为一个自称是全部记录而其实不是的文件比没有更糟。

**更早的条目按游标一页一页加载。**续读点名的是当前页上最早的那一条，于是往回翻的读者不会被管理员同时在做的事挪动。没有「还剩多少」这个数——部署钳住了页的大小，并且不说钳掉了多少——所以只要一页里有东西，按钮就提供；而一次续读回来是空的，才是「历史到齐了」这句话。

**被截断的值在它被截断的地方被标出。**部署只保留长内容的前一部分；那一行会说出哪个字段被缩短了、以及为什么，每个条目说一次。

<a id="model-experience"></a>
## 模型体验

没有，因为这个包不注册任何工具或提示词：它渲染一个配置界面，它展示的东西不会进入任何模型请求。

#### KV Cache 影响

没有请求前缀发生变化，因为这里没有东西参与组装一个请求。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- **一次导出到一万条就停** — 翻遍这份记录的那个循环必须自己决定在哪里停；撞到上界的读者会被告知文件是最新的一万条，而不是拿到一个被悄悄截断的文件。没有办法导出更早的那一段。
- **没有筛选也没有搜索** — 每一类、每一条记录、每一个管理员都混在一起显示；想找某一条记录历史的读者只能用眼睛找。
- **时间就是存下来的那个时刻** — 每个条目显示那份记录记下的 UTC 时刻，不是按读者自己的地区和时区格式化过的时间。
- **一条记录用它的 id 指称** — 一个条目点出那条记录的身份和它当时用的名字，而没有东西链接到它在人或机器人页上的那一行。
- **这个区块对每一个读者都提供** — 一个普通成员打开设置会看到它，并读到「他不能读这个组织的历史」这条提示，而不是根本没有这个区块。要把它藏起来，需要导航在这个区块自己的读答出来之前就知道调用方的身份。

**Runtime invariant:** 不发布伴生检查。这个区块从一次读渲染；不存在第二份可以和部署不一致的拷贝。
