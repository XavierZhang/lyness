# @deepseek-ai/dsh-bot-ask

[English](README.md) | 中文

## 概述

`dsh-bot-ask` 是队友之间协作的方式。一个 bot 向另一个提一个问题并等它的答复；若干个在一间由主持运行的房间里讨论同一个问题。每一轮都发生在它自己那个 bot 的一场对话里、以那个 bot 的性格和 preset 进行，回来的是为那个问题写的一段话——绝不是任何人的对话记录。团队成员身份就是全部的授权，而每一边都留着自己的那份记录。

<a id="use-this-package"></a>
## 使用本包

账户模块把两个服务都挂在名册旁边，并把那些工具贡献进每一个接受贡献行的 preset：

```yaml
- id: bot-ask
  name: '@deepseek-ai/dsh-bot-ask'
- id: bot-room
  name: '@deepseek-ai/dsh-bot-ask/room'
- id: bot-ask-tools
  name: '@deepseek-ai/dsh-bot-ask/preset-contribution'
```

没有要配置的。于是一个 bot 自己的对话里带上了 `list_teammates`、`ask_teammate` 和 `hold_discussion`；人打开的对话也带着它们，并读到一个空团队，因为那场对话不以任何 bot 的身份说话。

<a id="understand-the-implementation"></a>
## 理解实现

**问不是读。**被问的 bot 的那些对话属于打开它们的人，而[会话可见性](../session-ownership/README.zh.md)连那些人自己的同事都要拒绝。一个能读到它们的 bot，就是一条绕开产品在别处处处执行的规则的路，所以一次提问产出的是组织出来的答复，绝不是一段对话记录。

**作答的那一轮是它自己的会话，不是提问方的子代理。**一个子代理和它的父代理一样有权限，而且会以父代理的性格作答，那既不是两个 bot 中任何一个的。队友自己的一场会话带着队友的 preset、队友的性格和队友的名字。

**团队成员身份就是全部的授权。**这里读的那份名录正是管理员写下的那个关系。它带着作答那一轮运行所需的一切，所以不存在第二次读名册、也就不会和它不一致。

**一个答复是一次披露，所以两边都记下来。**提问方的会话记下它学到了什么、从谁那里学到；作答方的会话在那一轮开始之前就记下谁问了它什么，于是一场没答出来的会话仍然说得出它被问了什么。两个事件都不携带另一侧的对话。

**一间房间的主持是代码，不是参与者。**它决定下一个谁说、以及讨论何时结束，因为一个自己挑轮次的参与者，是谁也拦不住的那种。规则是轮询：每个参与者每轮说一次，按开场方点名的顺序，开场方在最前。更聪明的主持可以替换它；一间没有上界的房间事后无法被做成安全的。

**上界是部署的，而且是钳住而不是拒绝。**要求的轮数超过部署所主持的，就少跑几轮，因为一场更短的讨论是诚实的答复，而一次拒绝只是多给模型一个要恢复的失败。

**结论是主持自己的那次请求，用固定提示词。**从说过的话里写出，不用任何参与者的口吻：用某一个 bot 的口吻写出的结论就是那个 bot 的立场，而那正是一个主持绝不能添加的东西。主持自己那次请求什么也没产出时，房间照样结束并把这件事说出来——那些发言就是记录，缺一段总结不是丢掉它们的理由。

**一个参与者读这间房间，而且只读这间房间。**送给它的记录就是它被邀请进的那场讨论。这不是上面那条规则的缺口：任何其他对话的内容都不会到它那里。

**作答那一轮在提问方的目录里运行。**一个团队把两个 bot 放在一起，它们共享提问方正在做的那份工作，而一个没有目录的作答轮次，它的文件工具没有任何可读的东西。

<a id="model-experience"></a>
## 模型体验

### 工具 schema

#### 模型看到什么

生成的[那些 schema](../../../docs/tool-catalog.zh.md#deepseek-aidsh-bot-ask)：`list_teammates` 不取参数；`ask_teammate` 取 `teammate` 和 `question`；`hold_discussion` 取那些 id、一个问题和一个轮数。`ask_teammate` 的描述说明了它不会返回什么——队友的那些对话——以及问题必须自带上下文，因为队友看不到提问方的对话。

#### Token 影响

在每一个其 preset 接受贡献行的 agent 上有固定的 schema 开销。

#### KV Cache 影响

前缀稳定；两个 schema 都不在运行时变化。把账户模块打开或关掉会让前缀变一次。

### 队友名录

#### 模型看到什么

每个队友一行：`<名字> (<id>) — <职责>`。一个不以任何 bot 身份说话的对话读到 `you are in no team, so there is nobody to ask`，这说明了情况而没有点出任何人的 bot。

#### Token 影响

每个队友一行短文本，在模型主动要这份列表时才读，不是每个请求都带着。

#### KV Cache 影响

只追加；结果跟在可复用的请求前缀之后。

### 讨论

#### 模型看到什么

每条发言写成 `<名字>: <发言>`，按顺序排列，然后是 `Conclusion:` 和主持写的那段话。每个参与者收到的是那个问题、到此为止的记录，以及轮到谁了；第一个发言的人读到 `Nobody has spoken yet.`。一次拒绝会点出是哪条规则挡住了它：这场对话不以任何 bot 的身份说话、某个参与者不是队友，或者没有点到别人。

#### Token 影响

调用的那一轮收到每条发言加上结论，一次。参与者自己那些轮次和主持那次总结请求的 token 花在它们自己的会话里，不会进入这个请求。n 个参与者 r 轮的一场讨论花掉 n×r 个发言轮次加一次主持请求，这正是上界存在的原因。

#### KV Cache 影响

在调用方会话里只追加；每个参与者那一轮都是一场新会话，没有可复用的共享前缀。

### 答复

#### 模型看到什么

`<名字> answered:`，后面是那个队友自己的会话记录下来的那段话。绝不是它的对话。一次拒绝会点出是哪条规则挡住了这次提问：这场对话不以任何 bot 的身份说话、目标不是队友，或者作答那一轮什么也没产出。

#### Token 影响

队友的完整答复，一次，落在提问的那一轮里。作答那一轮自己的 token 花在队友的会话里，不会进入这个请求。

#### KV Cache 影响

只追加；每个答复跟在可复用的请求前缀之后。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- **一间房间是一份记录，不是谁都能加入的一场对话** — 房间会话里存着说过的话和那个结论，之后不再有东西追加进去。人不能在里面发言，讨论一开始之后也不能再加参与者。
- **主持不能提前结束** — 轮询会把上界允许的每一轮都跑完，即使参与者已经达成一致，所以一个已经定下来的问题仍然要花掉剩下的那些轮次。
- **一场讨论由一个 bot 开，不是由人开** — 开场方必须是一个有队友的 bot。没有任何界面让一个人把若干个 bot 召集起来。
- **每一次提问都开一场会话** — 作答那一轮每次都是一场新对话，这正是它可审计的原因，也是一个繁忙团队会攒下会话的原因。没有东西复用或清理它们。
- **作答那一轮按部署的默认权限运行** — 而不是提问方会话的权限。一场被人收紧过的对话仍然可以问出去，而队友按部署默认作答，那是基线而不是提权；把提问方的政策带过去这件事延后了。
- **没有人类审批闸口** — 设计为三件事保留了一个：够到组织之外、超出提问方的配额、以及以更强的权限预设行动。三者目前都够不到：队友在构造上就是同组织的、没有挂任何计量、作答那一轮也不会继承更强的政策。
- **不能按 bot 选模型** — 作答那一轮用部署的默认模型，因为 bot 记录里没有模型这一项。
- **提问的 bot 要等** — 一次提问会阻塞提问方那一轮，直到队友答出来。没有办法同时问几个队友，也没有办法先问、以后再收。
- **提问方的目录是共享的** — 一个带文件工具的队友读得到提问方工作区里的东西。那是提问方自己的工作、提问也是它自己发起的，但这仍是一次披露，管理员在把一个有文件能力的 bot 放进团队时应当知道。

**Runtime invariant:** 不发布伴生检查。这个服务不拥有任何状态：授权是名册的，两条记录是会话自己的日志。
