# @deepseek-ai/dsh-invitations

[English](README.md) | 中文

## 概述

`dsh-invitations` 是一个陌生人成为成员的那条路，也是一个已经在这里的人获得第二个身份的那条路。管理员签发一张携带**一个标准**的码——一个角色，以及它所在的组织——并把它发出去。陌生人在登录处出示它，出来时就是名册上一条带着**正是那个标准**的记录；已经在名册上的人则自己接受它。码就是授权，而它四面都有边界：它授出的不会多于签发者本可以直接授出的、它会过期、它只允许被兑换计数内的次数、可以被撤回，并且随签发它的那个标准一同作废。部署只存它的哈希。

<a id="use-this-package"></a>
## 使用这个包

两行：邀请码本身，以及**取代** `dsh-managed-people/admission` 的那条准入规则。

```yaml
- id: invitations
  name: '@deepseek-ai/dsh-invitations'
  config:
    defaultLifetimeMs: 604800000
    defaultMaxUses: 1
- id: sign-in-admission
  name: '@deepseek-ai/dsh-invitations/admission'
  config:
    bindings: []
```

一个部署只挂一条准入规则。受管那条只准入管理员绑定过的人；这一条还准入他们邀请过的人。`bindings` 是两条规则读的同一份「运维写定」的半边，所以换行不会丢掉一套安装自己写下的东西。

浏览器那一半负责携带这张码：`/auth/sign-in/<channel>?invite=<code>` 把它放进一只短命 cookie，等目录返回时再出示。**码不会走到目录那边去。**

<a id="understand-the-implementation"></a>
## 理解实现

**库里没有可兑换的秘密。** 码只由签发它的那次调用返回一次，之后只留 SHA-256。管理员丢了就再签一张；没有任何东西能把它读回来——包括被偷走的存储。

**它授出的，是签发者手里的，而且验两遍。** 名册「直接加人」用的那三条规则在签发时再用一遍：租户管理员的标准必须写明组织、只有超级管理员能造出另一个超级管理员、谁也伸不出自己管理的组织之外。然后兑换时会再问一次目录：签发它的那个标准还在不在——被移除、被降级、被挪走的管理员签的码，谁都准入不了。

**名册先答，邀请码后答。** 已经被绑定过的主体就以那个人的身份登录，他手里恰好还有张码也不改变什么。正是这个顺序，使一张被转发的链接不会为「已经在这里的人」再加一条记录——也不会在他为别的事情登录的那一次里，往他的账户上加授权。

**已经在这里的人，自己接受。** `accept` 是另一半，而且刻意不是同一半：那个人已经登录、码由他自己出示、身份之所以到账是因为他提出了要求。它授出的不多于签发标准本可以直接授出的，因为这次写入是**以那个标准**经名册完成的——包括名册那条「改一个人要管得着他的每一个身份」。

**被拒的接受不花掉邀请码。** 次数是在写入之前占的，名册拒绝时再放回去，因为别的什么都没有被写。兑换做不到这一点——它的绑定失败时会留下一个人——而被拒的接受让部署原样不动，为一句「不行」烧掉管理员的一张码是更差的交换。

**先占用次数，再写名册。** 两次兑换并发也不会超出计数；占了之后写失败会烧掉一次使用机会——这是安全的那一侧：多出来的成员无法撤回，而烧掉一次只是再发一张码。

**写不完的名册会被回滚。** 人是在「以他身份登录的那个目录身份」之前被写下的，所以绑定被拒时那个人会被重新移除：一行「谁都当不成」的记录，是管理员没要过、也解释不了的。这个失败是**抛出来**的，而不是答成「未被准入」——出示码的那个人没做错任何事，而一个谁都准入不了的部署应该说出来。

**所有拒绝都是同一个答案。** 码不对、已用完、已过期，以及根本没被邀请的主体，一律答 `undefined`，由登录流程报成 `not-admitted`。会把它们区分开的页面，等于向任何来问的人报告「哪些码存在」。

**撤回保留记录。** 撤回只写 `revokedAt`，不删行：留着这条记录的意义正是「谁邀请了谁」这条轨迹，删掉之后有人问「这个人怎么进来的」就无从回答了。

<a id="model-experience"></a>
## 模型体验

无：这个包不注册任何工具或提示词，它回答的是「谁可以加入」，发生在任何会话之前。

#### KV 缓存影响

不改变任何请求前缀，因为这里没有任何东西参与请求组装。

## 已知限制与未完成事项

<a id="known-limitations-and-deferred-work"></a>

- **接受不会告诉持有者关于这张码的任何事**：码不对、已用完、签发者已不在、携带的是他已持有的身份——四种答案一模一样，否则任何登录了的人都能从中得知哪些码存在。
- **兑换不是一个事务**：先占次数、后写名册，两者之间失败会烧掉一次使用机会而没有准入任何人。被拒的绑定会把自己那一半收回去：那个人会被重新移除，烧掉的那次使用是唯一留下的痕迹。
- **一张码只带一个标准**：一个角色、一个组织，所以邀请同一个人进两个组织是两张码。
- **不发邮件**：部署只负责产出码，怎么送出去是管理员自己的事，用他本来就在用的渠道。
- **撤回后标签仍保留**：标签是管理员自己写的那行字，所以写了邮箱的标签会把那个邮箱留在轨迹里。

**运行期不变量：** 没有任何邀请码授出的多于签发者此刻仍持有的；签发它的那次调用之后，没有任何码可被读出。
